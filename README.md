# ระบบลงเวลาด้วยลายนิ้วมือ (Google Apps Script)

พนักงานเปิดลิงก์บนมือถือ แตะปุ่มหน้าปัด สแกนลายนิ้วมือ ระบบบันทึกเวลา เข้า/ออกงาน พร้อมพิกัด GPS ที่อยู่ และระยะจากสถานที่ทำงานลง Google Sheet อัตโนมัติ

## ติดตั้ง (ครั้งเดียว)

1. ส่งโค้ดขึ้น Apps Script: `clasp push` (หรือคัดลอกไฟล์ `Code.js`, `Db.js`, `WebAuthn.js`, `SelfTest.js`, `SampleData.js`, `Buttons.js`, `Index.html`, `appsscript.json` ไปวางเอง)
2. ในตัวแก้ไข Apps Script เลือกฟังก์ชัน `setup` แล้วกด Run อนุญาตสิทธิ์ ระบบจะสร้าง Google Sheet และแผ่นงานทั้งหมด ลิงก์ Sheet อยู่ใน Execution log
3. เลือกฟังก์ชัน `selfTest` แล้ว Run ต้องขึ้น `OK ... ms` (ยืนยันว่าตรวจลายนิ้วมือฝั่งเซิร์ฟเวอร์ทำงานได้)
4. เปิด Sheet แล้วแก้ข้อมูลเริ่มต้น
   - **สถานที่ทำงาน**: ใส่ชื่อ ละติจูด ลองจิจูด และรัศมี (เมตร) ของที่ทำงานจริง ดูพิกัดได้โดยคลิกขวาที่จุดบน Google Maps แล้วคัดลอกตัวเลข แนะนำรัศมี 100–200 ม. เผื่อ GPS คลาดเคลื่อน เพิ่มได้หลายแถว
   - **พนักงาน**: ใส่รหัสพนักงานและชื่อ
   - **ตั้งค่า**: เปลี่ยน `COMPANY_NAME` และตัวเลือกอื่นตามต้องการ
5. (ไม่บังคับ) เลือกฟังก์ชัน `loadSampleData` แล้ว Run เพื่อใส่ข้อมูลตัวอย่าง: พนักงาน E002–E006, สาขาเพิ่ม 1 แห่ง และประวัติลงเวลาย้อนหลัง 5 วันทำงาน (รวมตัวอย่างนอกพื้นที่) ใช้ดูหน้าตา Sheet ก่อนเริ่มจริง เมื่อพร้อมให้ Run `clearSampleData` ลบเฉพาะข้อมูลตัวอย่าง ข้อมูลจริงไม่ถูกแตะ
6. สร้างรหัสลงทะเบียน: ในแผ่นงาน **พนักงาน** ติ๊กช่องใต้หัวข้อ "ติ๊กช่องข้างล่าง = สร้างรหัสให้ทุกคน…" (ช่อง I2) ระบบจะสร้างรหัส 8 ตัวอักษรลงช่อง "รหัสลงทะเบียน" ให้ทุกคนที่ยังไม่มีเครื่อง แล้วติ๊กออกเอง (ใช้ได้ครั้งเดียว หมดอายุใน 72 ชั่วโมง) ช่องติ๊กนี้ถูกสร้างตอนรัน `setup` ครั้งแรก ซึ่งจะขออนุญาตสิทธิ์เพิ่มเรื่องทริกเกอร์ (รัน `setup` ซ้ำได้ถ้าเพิ่งอัปเดตโค้ด) ถ้าไม่ใช้ช่องติ๊ก จะรันฟังก์ชัน `generateRegistrationCodes` แทนก็ได้
7. Deploy → New deployment → Web app (ค่าใน `appsscript.json` ตั้งไว้แล้ว: Execute as: Me, Who has access: Anyone) แล้วคัดลอก URL ที่ลงท้ายด้วย `/exec` ไว้ ทดสอบว่า API ทำงานด้วยการเปิด `<URL>?fn=config` ในเบราว์เซอร์ ต้องเห็น JSON ขึ้นต้นด้วย `{"ok":true`
8. **โฮสต์หน้าเว็บนอก Apps Script (จำเป็น)** Google ไม่เปิดสิทธิ์ลายนิ้วมือ (WebAuthn) ให้หน้าที่แสดงในกรอบของ Apps Script จะขึ้นว่าถูกบล็อกโดย permissions policy หน้าที่ใช้สแกนจริงจึงอยู่ในโฟลเดอร์ `docs/` ซึ่งต้องเปิดเป็นหน้าหลักของเบราว์เซอร์:
   1. แก้ `docs/config.js` ใส่ URL `/exec` จากข้อ 7 ที่ `window.FS_API`
   2. อัปโหลดโปรเจกต์ขึ้น GitHub (repo ใหม่ ตั้งเป็น public ถ้าใช้ Pages ฟรี) แล้วไปที่ Settings → Pages → Source: Deploy from a branch, Branch: `main`, Folder: `/docs`
   3. รอ 1–2 นาที ลิงก์จะเป็น `https://<ชื่อผู้ใช้>.github.io/<ชื่อ repo>/` ส่งลิงก์นี้ให้พนักงาน (ใช้ Netlify, Cloudflare Pages หรือ Firebase Hosting แทนได้ ขอแค่เป็น https และชี้ไปที่โฟลเดอร์ `docs/`)
   4. ลายนิ้วมือผูกกับโดเมนของหน้านี้ ถ้าเปลี่ยนโดเมนภายหลัง พนักงานต้องลงทะเบียนใหม่
   - ไฟล์ `.claspignore` กันไม่ให้ `clasp push` ส่งโฟลเดอร์ `docs/` ขึ้น Apps Script (ถ้าหลุดขึ้นไป `config.js` จะทำให้สคริปต์ error)

ถ้าสคริปต์นี้ผูกกับ Google Sheet อยู่แล้ว (สร้างจาก Extensions → Apps Script) ระบบจะใช้ Sheet นั้น และมีเมนู **ลงเวลา** ให้กดแทนการรันฟังก์ชัน

## พนักงานใช้งาน

1. เปิดลิงก์ของหน้าเว็บ (ข้อ 8 ข้างบน ไม่ใช่ลิงก์ `/exec`) บนมือถือ กด "ลงทะเบียนลายนิ้วมือ" ใส่รหัสพนักงานกับรหัสจากแอดมิน แล้วสแกนนิ้ว (ทำครั้งเดียวต่อเครื่อง)
2. ครั้งต่อไปแตะหน้าปัดแล้วสแกนนิ้ว ครั้งแรกของวันคือเข้างาน ครั้งถัดไปคือออกงาน เลือกบังคับ "เข้างาน/ออกงาน" ได้ที่แถบด้านล่าง
3. ใช้เหมือนแอป: เปิดลิงก์ใน Chrome แล้วเลือก "เพิ่มไปที่หน้าจอหลัก" (iPhone: Safari → แชร์ → เพิ่มไปยังหน้าจอโฮม)

## งานของแอดมิน

| สถานการณ์ | ทำอย่างไร |
|---|---|
| พนักงานเปลี่ยนมือถือ / มือถือหาย | ในแผ่นงาน **อุปกรณ์ลายนิ้วมือ** ใส่ `FALSE` ที่คอลัมน์ใช้งานของเครื่องเก่า แล้วติ๊กช่องในคอลัมน์ G "สร้างรหัสใหม่" ของพนักงานคนนั้น |
| เพิ่มเครื่องที่สอง | ติ๊กช่องในคอลัมน์ G "สร้างรหัสใหม่" ของพนักงานคนนั้น (หรือพิมพ์รหัสเองในช่องรหัสลงทะเบียนก็ได้) |
| พนักงานลาออก | ในแผ่นงาน **พนักงาน** ใส่ `FALSE` ที่คอลัมน์ใช้งาน |
| ไม่ให้ลงเวลานอกที่ทำงาน | แผ่นงาน **ตั้งค่า** ตั้ง `BLOCK_OUTSIDE` เป็น `TRUE` |
| ดูผลลงเวลา | แผ่นงาน **บันทึกเวลา** (ลิงก์แผนที่อยู่ในคอลัมน์ แผนที่) |

คอลัมน์ "ใช้งาน": เว้นว่างถือว่าใช้งาน ปิดเมื่อใส่ `FALSE`

## ความปลอดภัยและข้อจำกัด

- ใช้มาตรฐาน WebAuthn (Passkey) ลายนิ้วมือจริงไม่ออกจากเครื่อง เซิร์ฟเวอร์เก็บเฉพาะ public key และตรวจลายเซ็นของทุกการสแกน (challenge ใช้ได้ครั้งเดียว ตรวจตัวนับป้องกันการเล่นซ้ำ)
- ผู้ที่ควบคุมการลงทะเบียนคือแอดมิน: ใครได้รหัสลงทะเบียนก็ผูกเครื่องของตัวเองได้ จึงควรแจกรหัสเป็นรายคน
- พิกัดมาจากมือถือ แอปปลอมตำแหน่ง (mock location) บนเครื่องที่ root/jailbreak อาจหลอกได้ ระบบไม่สามารถตรวจจับได้
- WebAuthn ผูกกับโดเมนของหน้าเว็บ (โดเมน GitHub Pages ของคุณ) ถ้าย้ายไปโดเมนอื่น พนักงานต้องลงทะเบียนใหม่
- ใครก็ทำหน้าเว็บของตัวเองมาเรียก API นี้ได้ แต่ลงเวลาได้เฉพาะเครื่องที่ลงทะเบียนด้วยรหัสจากแอดมินแล้ว และลายเซ็นผูกกับโดเมนที่ลงทะเบียนไว้
- ปุ่ม ? ในหน้าเว็บมี "ตรวจสอบเครื่อง" บอกว่าเครื่องและหน้านี้ใช้ลายนิ้วมือและตำแหน่งได้หรือไม่
